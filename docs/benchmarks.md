# Reproducible measurement protocol

Phase 1 runs are correctness smoke records, not performance benchmarks. Use `research/benchmarks/run_phase1.py` with a fixed spec and a new `research/runs/local/<run-id>` directory. It captures input hash and size, source Git SHA and dirty flag, exact command, exit status, versions, CPU/RAM/OS metadata where available, wall time, child CPU and peak RSS with explicit units, stdout/stderr and witness/replay paths. Missing machine facts remain null. The script does not aggregate one run into a speed claim.

A future comparative benchmark requires a frozen workload and license, identical or explicitly mapped obligations, isolated installs, timeout and memory limits, warm/cold cache rules, justified repeat count, failure accounting, variance and uncertainty. Run query-identifiability and VeriEQL only on accurately mapped fragments; an unsupported obligation is not a baseline failure. The local exhaustive enumerator is a small correctness reference rather than a scalability baseline. Record negative results and baseline wins in the claims ledger.

## Phase 2 paired tiny reference

`PYTHONPATH=src .venv/bin/python research/benchmarks/compare_tiny_reference.py examples/no_undo/daily_distinct.json --repeats 5 --output research/runs/local/paired.json` repeats the *same* finite obligation against the exhaustive enumerator and Z3 search and validates every solver witness in DuckDB. It records every sample, status, world count, software environment and timing, plus median/min/max without discarding failures. The protocol is warm, paired, in-process, reference first, with no CPU or cache isolation. It is a correctness and harness regression, not a general speed comparison. A one-workload timing difference cannot establish algorithmic superiority or scalability.

After a clean committed run, `research/benchmarks/publish_manifest.py` checks the input hash, clean Git SHA, status, serialized world hash and replay SQL against the versioned witness before writing a sanitized portable manifest. It omits private absolute paths while retaining hashes of local raw logs. Those hashes document provenance but are path-dependent and not a byte-for-byte rerun target. The exact local raw run remains ignored; the published record states the transformation. No timestamp or measured value is edited.
