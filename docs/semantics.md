# NoUndo v0.1 semantics

For a database instance `D`, retained SQL queries `V` and scalar KPI `Q`, a witness is a pair of legal synthetic instances `D1,D2` for which every `V(D1)` and `V(D2)` is equal as an unordered multiset of typed rows and `Q(D1) != Q(D2)` under DuckDB scalar and NULL equality rules. SQL NULL compares equal to SQL NULL for result normalization, but SQL `COUNT(DISTINCT x)` omits NULL. The conclusion is limited to the declared schema and constraints; it says nothing about backups or other surviving data.

Initial input is JSON (YAML may be accepted after safe-loader tests) with one table of explicitly typed finite-domain columns, nullable flags, optional primary key, row bound, one retained query, one scalar metric, a timeout, seed and output directory. A row is an ordered tuple; a database is a bag of rows. Source row ordering is semantically irrelevant. Candidate worlds may have zero rows. Duplicate rows remain distinct bag entries. A primary key, if present, is unique and non-NULL. Any unsatisfiable schema/domain combination is reported as invalid input or a bounded empty legal space, as appropriate.

Supported SQL is a deliberately guarded subset of DuckDB `SELECT`: a single named table; direct grouping by one declared column; `COUNT(*)`, `COUNT(column)`, `COUNT(DISTINCT column)`, and `SUM(integer_column)`; aliases; and a scalar aggregate metric without `GROUP BY`. Every selected nonaggregate column must be the grouping key. No `WHERE`, joins, arithmetic expressions, `ORDER BY`, `LIMIT`, subqueries, windows, UDFs, recursive SQL, nondeterministic functions, or writes. The parser validates the complete AST and inferred argument types; accepting SQLGlot syntax alone never establishes semantic support. Date literals are finite ISO dates from the input domain. `SUM` on an empty input or an all-NULL group is SQL NULL; `COUNT` is zero. Integer overflow beyond DuckDB `BIGINT` is outside the Phase 1 domain and rejected by bounded input checks.

Result normalization records column order and typed values. View equality is `Counter(rows)` equality, preserving multiplicity; source row order and view output row order are ignored. The metric must return exactly one row and one column. NULL metrics are equal only when both NULL. No float values, approximate aggregates or collation dependent text semantics are admitted.

Statuses: `COUNTEREXAMPLE_FOUND` requires independent serialized DuckDB replay; `BOUNDED_NO_COUNTEREXAMPLE` requires complete finite search over stated bounds; `INCONCLUSIVE` covers timeout or candidate budget; `UNSUPPORTED` covers outside-fragment SQL; `INVALID_CANDIDATE` covers solver/replay or constraint disagreement; `PROVEN_WITHIN_FRAGMENT` is reserved for a later sound theorem. No universal preservation claim is made by the first slice.

Soundness threats: AST nodes omitted from validation, SQL NULL and empty-set behavior, bag versus set confusion, integer overflow, constraints interpreted differently by solver and DuckDB, search timeout labeled as exhaustive, and stale/incomplete replay artifacts. Each needs a negative or independent regression check before public use.
