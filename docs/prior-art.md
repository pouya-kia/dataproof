# Prior art and baseline feasibility

Checked on 2026-10-18 against project repositories and primary documentation. These are capability descriptions, not empirical comparisons or originality findings. Repository behavior and licenses must be rechecked before publication.

| Project | Established overlap | Observed relationship or limit |
| --- | --- | --- |
| [query-identifiability](https://github.com/danielhz/query-identifiability) | Relational query identifiability, closure certificates, witness discovery and view augmentation; README documents `make mini`; MIT | A local certificate smoke passed, but it did not encode the grouped-aggregate obligation. |
| [VeriEQL](https://github.com/VeriEQL/VeriEQL) | Bounded SQL equivalence with integrity constraints and counterexamples; documented Python and Z3 workflow | A local environment smoke failed on a Z3 `ctx` error; no comparable result was obtained. |

Local baseline investigations on macOS ARM, Python 3.11, isolated outside this repository:

- query-identifiability commit `f2626f65034c5eda03fc1937c4088a5ece8b9257`: `python3 -c 'from data.utils import check_certificate; f=frozenset({0,1}); print(check_certificate(f,[frozenset({0})],[])); print(check_certificate(f,[frozenset({0})],[(frozenset({0}),1)]))'` printed `False` then `True`. This runs the actual certificate code but does not encode the daily aggregate obligation. Its full `make mini` needs substantially larger optional research dependencies and has not been run.
- VeriEQL commit `493cbb81000205e33b0623cfd1c39106fa035fae`: isolated `pip install -r requirements.txt` succeeded, but `python -m test.test_env` failed at `TypeError: And() got an unexpected keyword argument 'ctx'` with `z3-solver` 5.3.1.0, 4.12.2.0 and 4.11.2.0. No equivalence result is available. This is an environment compatibility observation, not evidence that VeriEQL's method fails.

The second runnable baseline is `research/benchmarks/exhaustive_daily_baseline.py`, a standard-library complete enumeration of the tiny two-day/two-customer case. `python3.11 research/benchmarks/exhaustive_daily_baseline.py` printed `worlds=4 witness_pairs=8`, `D1=(1, 1) D2=(1, 2)`, `daily_equal=True`, and `monthly_distinct=1,2`. Thus Phase 0 examines two runnable baseline mechanisms, but **not two directly comparable external competitors**. No direct competitor has yet been run on an identical NoUndo obligation. No speed, coverage, superiority or novelty claim is supported. Licensing of VeriEQL and SQLSolver is not verified here; do not copy their code. DuckDB replay remains a separate Phase 1 control and cannot replace a fair competitor evaluation. See `research/literature/related_work.csv` for the artifact matrix.

Code-level relation after Phase 1: DataProof's `solver.py` encodes aggregate group counts/SUM/DISTINCT for two finite worlds and `replay.py` checks the original SQL in DuckDB. query-identifiability's `data/utils.py` computes FD closure/certificates for relational views, with witness code elsewhere; our certificate smoke tests only its closure operation. VeriEQL's `environment.py`/`test/test_env.py` checks bounded equivalence between two SQL queries over a shared database; its published smoke did not complete here due the Z3 `ctx` API error. Neither observation supports a novelty or performance claim. A fair reduction of the same daily aggregate obligation to both tools remains open.

Phase 2 code-level follow-up, 2026-10-18: [query-identifiability `data/witness.py`](https://github.com/danielhz/query-identifiability/blob/main/data/witness.py) explicitly searches pairs of worlds with equal FD-closed overlap projections and different **Boolean conjunctive-query** answers, using directed mutation or sampling. Its input observation is relational projection, not the grouped `COUNT`/`SUM`/`COUNT DISTINCT` view admitted here. Replacing the aggregate with a projection changes the obligation, so we did not report a timed head-to-head result. [VeriEQL's `test/test_env.py`](https://github.com/VeriEQL/VeriEQL/blob/main/test/test_env.py) passes two SQL queries over a single bounded schema to `Environment.analyze`; its [README](https://github.com/VeriEQL/VeriEQL) describes bag semantics and SQL-pair benchmarks. A NoUndo test needs **two legal worlds constrained to have equal view results** and unequal KPI results. An ordinary same-world query-equivalence call is not that obligation; a verified two-world encoding and compatible integrity constraints are still missing. Its previous environment smoke remains blocked by the recorded Z3 `ctx` error, not counted as a negative algorithmic result. The only same-obligation timed baseline in Phase 2 is our exhaustive tiny reference; no external comparative performance or novelty claim follows.
