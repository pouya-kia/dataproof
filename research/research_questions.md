## RQ N1, 2026-10-18

Can a restricted, offline NoUndo search produce small legal two-world counterexamples for analytical aggregate view determinacy that survive independent DuckDB execution, while accurately distinguishing finite bounded misses from fragment-level proofs? The falsifiable Phase 1 hypothesis is that the daily `COUNT(*)`, `SUM(amount)`, and `COUNT(DISTINCT customer_id)` example yields a replayable witness and that tiny-domain Z3 results agree with a separate exhaustive reference. The competing explanation is that existing query-identifiability or SQL equivalence tools already provide equivalent witnesses with equal or better support and that DataProof adds only packaging. A solver/replay mismatch, any false witness, or a baseline that subsumes the claimed workflow defeats a stronger claim. The independent oracle is DuckDB execution of serialized worlds and source SQL; the baseline is exhaustive finite enumeration plus direct competitor experiments when runnable.

No scoped positive theorem, measured scalability, or novel method has been established.

## RQ N5, Phase 2 hardening, 2026-10-18

Can an expanded finite-domain differential and mutation corpus expose inconsistencies among DataProof's Z3 encoding, separate exhaustive evaluator and DuckDB execution before a bad witness is published? The falsifiable hypothesis is that all admitted tiny NULL/bag/key/aggregate configurations agree and deliberate COUNT DISTINCT corruption is detected; a solver/reference mismatch, accepted invalid replay or silent backend exception refutes the hardening claim. The competing explanation is that a finite generated corpus misses a shared semantic bug or that established verification tools already provide stronger coverage. The reference baseline is exhaustive enumeration of the exact finite worlds, the independent execution oracle is DuckDB on the original SQL, and the supported SQL fragment remains unchanged from Phase 1. This is a quality-control hypothesis, not a new scientific novelty claim.

## RQ N6, Phase 3 guarded fragment, 2026-10-18

Can single-column row filters and direct integer MIN/MAX enlarge useful bounded NoUndo obligations while preserving agreement among Z3, exhaustive finite enumeration, and independent DuckDB execution? The falsifiable hypothesis is that every accepted query in the expanded fragment agrees on tiny legal worlds, including empty/all-NULL groups, duplicate rows, and SQL NULL filtering, and that every emitted witness replays. One disagreement or accepted unmodeled SQL shape refutes this scoped claim. The competing explanation is that these operators are routine engineering coverage already present in established query-identifiability or SQL verification systems; no methodological novelty follows from adding them. The baseline is exhaustive enumeration, with direct competitor comparison only if a comparable runnable configuration is established. The execution oracle is DuckDB on original SQL, not SQL regenerated from the IR. Experiment outputs and limitations must be recorded at an exact commit; no result is asserted before execution.
