# Phase 5 Proof2Test checkpoint

The falsifiable question was whether a replay-validated Doppelgänger witness plus a separately declared target expectation can yield an executable test that rejects a defective SQL transformation and accepts a corrected one on the same synthetic input. The null explanation was a circular test that merely checks witness presence or `BLIND_SPOT_FOUND`. Status: `SUPPORTED_WITHIN_SCOPE` for one guarded, finite example and the regression corpus; not a general repair result, universal target guarantee, or novelty finding.

The [clean, sanitized run](../runs/published/phase5-6c1fd5e.json) is pinned to source commit `6c1fd5eb0c0fe2405755c702feaaa6c7f7557e73` with `git_dirty_before_run=false`. The [protocol](../protocols/phase5.md), [reproduction harness](../benchmarks/run_proof2test.py), [target contract](../../examples/proof2test/clamp_amount.contract.json), [versioned pytest fixture](../../examples/proof2test/generated_pytest/fixture.json), and [dbt unit-test YAML](../../examples/proof2test/generated_dbt/unit_tests.yml) document the exact synthetic scope. The harness generated a fresh legal one-row witness, independently validated its source assertions and serialized replay, exported the test twice byte-identically, then actually ran it. The defective identity SQL exited 1 with `target output bag differs` (`((-1,),)` versus declared `((0,),)`); the same generated test on the declared clamp SQL exited 0 with one passed test. A modified fixture exited 1 for hash mismatch. A real isolated dbt-duckdb unit-test run likewise failed on the defective model and passed on the corrected model.

The recorded environment was macOS arm64, Python 3.11.16, DuckDB 1.5.6, SQLGlot 29.0.1, dbt Core 1.10.23 and dbt-duckdb 1.10.0. One sequential research run measured witness check 0.167 s, serialized replay 0.117 s, export 0.120 s, repeat export 0.119 s, generated defective pytest 0.289 s, corrected pytest 0.233 s, tampered pytest 0.206 s and the dbt integration test 3.661 s. These are individual wall-clock observations without repeats, variance or an external baseline; no relative performance claim is supported. Raw artifacts are retained locally under ignored `research/runs/local/` and are not downloadable from the public manifest. The manifest contains hashes but no user paths or private notes.

Engineering controls include witness row/SQL/evaluation/replay tampering; false expected outputs; missing or unsupported target contracts; SQL DDL/DML, joins and unsupported projections; SQL UNKNOWN; missing target; output collision and symlink rejection; deterministic regeneration; empty input/output; NULL; duplicate bags with nullable UNIQUE; primary-key violations; a target backend fault; and property-based target/bag checks. The fresh installed Wheel generated and ran the same defective-FAIL/corrected-PASS pytest fixture while existing NoUndo and Doppelgänger CLI/replay and direct DuckDB `REPLAY_OK` remained intact. The full pre-implementation-commit gate reported 171 passed tests, Ruff/format/mypy/audit/build/fresh-install success. The final evidence-commit gate is reported separately in the milestone handoff.

The strongest counterevidence to novelty is that [dbt Core](https://docs.getdbt.com/docs/build/unit-tests) already supplies the `given`/`expect` unit-test format; [XData](https://arxiv.org/abs/1411.6704) studies constraint-generated SQL mutation-killing data; [Spec-Lock-Diff](https://github.com/miloskimatheus/spec-lock-diff/) offers related dbt mutation checks; and [Hypothesis](https://hypothesis.readthedocs.io/) already generates and shrinks Python test data. DataProof did not run any fair same-task competitor comparison. The likely useful contribution is workflow integration and validated witness provenance, still unproven as a scientific contribution. The cheapest falsifying follow-up is a same-contract export/detection study against existing dbt, property-based and mutation approaches over realistic models and independently reviewed expectations; Phase 5 does not authorize implementing that broader study or later modules.
