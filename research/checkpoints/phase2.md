## Corrective artifact-lifecycle milestone, 2026-10-18

A new regression reproduced a real output-contract bug: after `COUNTEREXAMPLE_FOUND`, a bounded result could replace `result.json` while leaving the old `witness.json` and `replay.sql`. The regression failed before the fix. DataProof now maintains a hash-checked ownership record for its fixed artifact names, removes only unchanged recorded files before a serial rerun, and refuses directories with unowned or modified reserved files. Non-success statuses do not retain current-run witness/replay files, including a backend exception after candidate files have moved. Invalid schema input can use a safely parsed embedded output path; syntactically malformed input needs explicit `--output`. Without either path, no directory can be safely inferred. Legacy directories lacking the ownership record must be archived or replaced with a fresh output directory. No unrelated file is deleted by the regression cases.

The corrective local affected/full suite passed 75 tests after the implementation and test adjustment; CI results belong to the corrective PR, not the earlier clean research manifest.
