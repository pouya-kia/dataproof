# Phase 4 Doppelgänger checkpoint

The scoped question is whether one legal synthetic dataset can make all explicitly declared existing tests SQL TRUE while making a separately justified business invariant SQL FALSE. Status: `SUPPORTED_WITHIN_SCOPE` for the finite example and tested fragment, not for arbitrary SQL or real business truth. The [input](../../examples/doppelganger/nonnegative_amount.json) declares one table, integer amount domain `[-1, 0, 1]`, at most two bag rows, a nonempty-table test and an independent no-negative-amount invariant. The one-row witness `amount = -1` passes `COUNT(*) >= 1` (count 1, TRUE) and violates `COUNT(*) WHERE amount = -1 = 0` (count 1, FALSE). DuckDB executed the original accepted SQL, accepted the legal row and serialized replay, and the generated SQL returned `REPLAY_OK`. A zero-row violating witness is impossible because the declared test requires at least one row; Z3 also checked the no-smaller-row obligation UNSAT within this finite bound.

The actual [sanitized clean-run record](../runs/published/phase4-e584070.json) is pinned to source commit `e584070e5d7dda257afe33c1fed44bc5f7703af3`, with the input hash, timestamp, versions, configuration, five raw timing samples, cumulative parent-process resource metadata, output hashes and reproduction command. It was produced on macOS arm64, Python 3.11.16, DuckDB 1.5.6, Z3 5.3.1 and SQLGlot 29.0.1. There were no solver/reference disagreements, timeouts or UNKNOWNs in these five runs. Each Z3 run found one row; the independent DuckDB exhaustive reference enumerated 10 legal worlds and found 9 test-passing worlds. The seeded random generator found a valid witness in all five trials, after 8, 2, 4, 2 and 2 draws (20-draw cap). Median measured solver time was 0.001914625 s (range 0.001839708–0.003986666); median exhaustive-reference time was 0.034869625 s (range 0.034516834–0.039239291). These methods do different work in one warm process without isolation, so the values do not support a speed or reliability comparison. The reported 98,615,296-byte peak RSS is cumulative parent-process metadata, not per-method memory use. Raw logs and artifacts are ignored local files; the published hashes do not make them downloadable.

Negative and adversarial regression cases distinguish a bounded miss from inconsistent tests; reject SQL UNKNOWN as a passing test or confirmed invariant failure; exercise NULL, bags, keys, unsupported SQL, solver/backend faults, invalid candidates and artifact tampering; and preserve NoUndo behavior. A finite test corpus cannot establish universal soundness. Supported inputs are one table, finite INTEGER/DATE domains, up to three rows, one to four named scalar-aggregate test assertions, one separate invariant and guarded read-only SQL. There is no dbt adapter, arbitrary Python test, production connection, multi-table join, or automatically inferred business rule. A bounded unsuccessful search is not a proof of test adequacy.

The strongest competing explanation is that established tools already cover much of the test-adequacy and witness-generation problem. [dbt tests](https://docs.getdbt.com/reference/resource-properties/data-tests), [Spec-Lock-Diff](https://github.com/miloskimatheus/spec-lock-diff/) and [XData](https://arxiv.org/abs/1411.6704) provide overlapping capabilities; none was run here on the exact declared-test/invariant obligation. No external coverage, performance or novelty comparison is claimed.
