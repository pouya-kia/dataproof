# Phase 3 guarded-fragment checkpoint, 2026-10-18

Phase 3 adds two independently useful, conservative NoUndo SQL extensions: a single direct row predicate (`INTEGER =` signed integer literal, `IS NULL`, `IS NOT NULL`) in either query, and direct integer `MIN`/`MAX` in grouped views or scalar metrics. Parser, Z3 and separate exhaustive evaluator all implement each admitted shape. DuckDB executes the original source SQL on generated worlds and serialized witnesses; no AST-to-SQL rewriting serves as the oracle. The full admitted grammar and exclusions are in `docs/semantics.md` and `docs/limitations.md`. In particular, compound predicates, DATE extrema, and scalar two-argument `MIN`/`MAX` are rejected. A failing regression first exposed that SQLGlot's `Min`/`Max` AST can hold extra arguments; explicit validation now rejects them.

Research question N6 is `SUPPORTED_WITHIN_SCOPE` only for the tested tiny finite cases. Exhaustive DuckDB differential tests cover filter equality inside/outside the domain, signed literals, NULL predicates, both grouped and scalar extrema, negative/all-NULL/empty semantics, and their combination. Property-driven Z3/reference agreement varies NULL and unique-key cases; row-order and bag checks protect the filter semantics. Injected filter-bypass and broken-MAX reference mutations are detected against DuckDB. Every generated CLI witness is replayed independently.
