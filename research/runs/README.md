# Run evidence

Phase 1 produces small, versioned JSON and replay SQL artifacts. Raw local runs may be ignored until reviewed. A manifest must cite its input, exact command, versioned environment and independently checked outcome. Record all failures and timeouts. Commit SHA must be captured after the code commit in a separate run record to avoid a circular hash. No precomputed result or benchmark is claimed here.

The reviewed synthetic example is `examples/no_undo/evidence/witness.json` plus `replay.sql`. The local pre-commit smoke run is `research/runs/local/smoke-1/manifest.json` and is intentionally ignored because its Git state is dirty. After the Phase 1 commit, rerun `research/benchmarks/run_phase1.py` into a new local directory so its manifest captures the exact commit SHA and clean state. Do not copy an old SHA into a new artifact.

Phase 2 publication procedure: first commit and validate the harness and golden witness. From a clean checkout of that exact commit, run `research/benchmarks/run_phase1.py` into a new ignored `research/runs/local/<id>` directory. Then use `research/benchmarks/publish_manifest.py` to verify the clean SHA, input hash, witness world hash, SQL replay hash and status, and write a small sanitized record under `research/runs/published/`. The publisher removes local absolute paths but retains actual timestamp, versions, measurements and raw-log hashes. This published record is a follow-up documentation commit: its `git_sha` identifies the code and harness that ran, not the later record commit. The ignored raw manifest and logs remain local; they are not an independently downloadable archive. Reproduce the result using the published command and compare status/world hash, not wall time or path-dependent stdout hash.
