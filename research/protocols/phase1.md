# Phase 1 protocol

Predeclare eight fixtures listed in `docs/testing-strategy.md`. Use fixed finite domains and seeds, two worlds each with at most the declared row bound. Record every timeout and negative case. Search returns a candidate only; DuckDB must independently validate both schema legality and original SQL view/KPI outputs from a serialized artifact. Any disagreement fails closed. An exhaustive enumerator checks tractable tiny domains. Witness minimization, if offered, must revalidate after each removal and never claim global minimality without complete argument.

The machine-readable manifest schema is `research/runs/manifest.schema.json` in Phase 1. Each run should include UTC timestamp, commit SHA (recorded after commit in an external or later verified run), input hash/size, seed, row/domain limits, timeout, memory cap, Python/SQLGlot/Z3/DuckDB versions, OS/CPU/RAM if available, solver result, replay result, command, exit code, stdout/stderr paths, and witness paths. Unknown metadata must be null or omitted, never inferred. Report repeats/variance only after measured runs.

Baseline plan: run the project's exhaustive reference on identical tiny obligations; attempt query-identifiability `make mini` and VeriEQL's documented bounded equivalence workflow in isolated environments. Map inputs/operators exactly and record incompatibilities. Never equate a competitor's different problem or dialect with a failed result. Retain failures and unavailable baselines. Public benchmark tables require version pins, licenses, resource limits, paired workloads, warm/cold protocol, and measured repetitions.
